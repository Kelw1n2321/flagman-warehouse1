# Флагман

Учёт склада ресторана: продукты, партии, сроки годности, заказы, стоп-лист и горячие предложения.

Сайт: https://flagman-warehouse.onrender.com

## Что умеет

- показывает остатки по каждому продукту и по партиям, у каждой партии свой срок годности
- принимает поставки (каждая строка поставки становится отдельной партией)
- проверяет заказ: если хоть какого-то продукта не хватает, заказ отклоняется и остатки не трогаются
- сам собирает стоп-лист из блюд, которые нельзя приготовить
- подсказывает, какие блюда продвигать, чтобы продукты не испортились (горячие предложения)
- считает статистику и прогноз, когда что закончится и что надо заказать
- ведёт журнал всех движений по складу
- есть светлая и тёмная тема и версия для телефона

## Как запустить

Нужны .NET 10 и Node.js 20 или новее.

Собрать интерфейс:

```bash
cd frontend && npm install && npm run build
```

Запустить сервер:

```bash
cd backend/Flagman.Api && dotnet run
```

Потом открыть http://localhost:5080. Локально ID для входа `1001` (лежит в `appsettings.Development.json`).
При первом запуске создаётся база SQLite с демо-данными за неделю, сбросить их можно в настройках.

Если правишь интерфейс, удобнее `cd frontend && npm run dev`, тогда он открывается на http://localhost:5173
и сам обновляется при изменениях.

Через Docker с PostgreSQL:

```bash
ADMIN_IDS="1001:Максим" docker compose up --build
```

Сайт будет на http://localhost:8080. В этом режиме демо-данных нет.

## Вход

Без входа сайт ничего не показывает. Админ вводит свой ID и попадает на склад.

ID задаются одним из двух способов:

1. Переменная окружения `Auth__AdminIds`, например `1001:Максим, 1002:Анна`. После двоеточия идёт имя, оно видно в меню.
2. `Auth:AdminIdHashes` в `appsettings.json`. Там хранится не сам ID, а его хеш (PBKDF2), поэтому его можно держать
   в открытом репозитории. Строку для нового ID можно получить через `AdminDirectory.HashId("твой-id")`.

Вход живёт 12 часов. Чтобы ID нельзя было подобрать, больше 10 попыток в минуту делать нельзя.

## Деплой на Render

В репозитории есть `render.yaml`. В Render нужно выбрать New, потом Blueprint, выбрать этот репозиторий и нажать Apply.
После каждого пуша в main сайт пересобирается сам. Проверка, что сайт живой, идёт по адресу `/api/health`.

На бесплатном тарифе база лежит внутри контейнера, поэтому после перезапуска демо-данные создаются заново.

### Как считается склад

- Остаток продукта нигде отдельно не хранится, он считается как сумма его партий.
- Просроченная партия в остаток не входит и для блюд не используется. Её можно списать вручную или включить автосписание.
- Любая операция (приёмка, расход, списание, корректировка) записывается в журнал.
- Заказ: сначала считаем, сколько всего нужно каждого продукта, и сравниваем с остатком. Если чего-то не хватает,
  заказ сохраняется как отклонённый с причиной. Если всего хватает, продукты списываются по FEFO
  (сначала то, что раньше испортится) одной транзакцией.
- Блюдо попадает в стоп-лист, если какого-то продукта меньше, чем нужно на одну порцию.
  Раз в 30 секунд сервер проверяет сроки, потому что продукты портятся и без всяких действий.
- Сроки по умолчанию: больше 72 часов норма, от 24 до 72 скоро истекает, меньше 24 критично.
  Все даты считаются по часовому поясу ресторана (по умолчанию Москва).

### Горячие предложения

Для каждого продукта, у которого скоро истекает срок, ищутся блюда, где он используется. Каждому блюду ставятся баллы:

```
баллы = 100 × срочность × (0,35 + 0,65 × покрытие) × (0,5 + 0,5 × объём) × эксклюзивность
```

- срочность растёт от 0,4 до 1 по мере приближения срока
- покрытие показывает, какую часть продукта блюдо может израсходовать
- объём показывает, сколько порций нужно, чтобы израсходовать продукт
- эксклюзивность равна 1/√N, где N это сколько ещё блюд используют этот продукт

45 баллов и больше это высокий приоритет, от 20 средний.

### Прогноз

Берётся средний расход за последние 7 дней, и по часам моделируется следующая неделя. Так видно, когда продукт закончится,
когда блюдо уйдёт в стоп-лист и сколько надо заказать.

## API

Все запросы идут на `/api/v1`, без входа сервер отвечает 401 (кроме `/auth/*`).

| Метод | Путь | Что делает |
|---|---|---|
| POST, GET, POST | `/auth/login`, `/auth/me`, `/auth/logout` | вход, кто вошёл, выход |
| GET | `/stock` | остатки |
| GET | `/products/{id}` | карточка продукта |
| GET | `/batches` | партии и сроки |
| POST | `/batches/{id}/adjust`, `/batches/{id}/write-off`, `/batches/write-off-expired` | корректировка и списание |
| GET, POST | `/supplies`, `/supplies/{id}/receive`, `/supplies/{id}/cancel` | поставки |
| GET | `/supplies/recommendations` | что заказать |
| GET, POST | `/orders` | заказы |
| GET, PUT, POST | `/dishes` | блюда и рецепты |
| GET | `/stop-list`, `/hot-offers`, `/stats`, `/alerts`, `/summary` | мониторинг |
| GET, PUT | `/settings` | настройки |
| GET | `/events` | поток обновлений (SSE) |

## Демо-данные

18 продуктов, 12 блюд, 6 поставок и около 170 заказов за неделю. Специально есть проблемные места:
просроченный лосось, мало огурцов, сливки с критическим сроком и одна непринятая поставка.
Если её принять, блюда возвращаются из стоп-листа.
